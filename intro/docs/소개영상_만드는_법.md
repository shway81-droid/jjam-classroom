# 짬짬이 교실 1분 소개 영상 — 어떻게 만들어졌나

`intro/jjam-classroom-intro.mp4` 한 파일이 어떤 과정을 거쳐 나오는지 적어 둔 문서입니다.
짧은 사용법은 [`../README.md`](../README.md) 에 있고, 이 문서는 **왜 이렇게 만들었는지와
어디를 고치면 무엇이 바뀌는지**를 다룹니다.

---

## 1. 한눈에 보기

| | |
| --- | --- |
| 완성본 | `intro/jjam-classroom-intro.mp4` (약 12.4MB) |
| 크기·길이 | 1920×1080 · 30fps · **1653프레임 = 55.1초** |
| 소리 | 배경음악 + 효과음 셋, **내레이션 없음** |
| 음량 | 통합 −16.4 LUFS(유튜브 권장대), 트루피크 −2.0 dBFS(클리핑 없음) |
| 만드는 도구 | [Remotion](https://www.remotion.dev) 4.0.544 (React 19) |
| 본보기 | 딸깍 보결의 [1분 소개 영상](https://github.com/shway81-droid/ttalkkak-bogyul/tree/main/video) |

**영상 편집 프로그램을 쓰지 않습니다.** 장면이 전부 React 컴포넌트이고, 프레임 번호를
받아 그 순간의 화면을 그립니다. 그래서 글자 하나를 고치는 일이 "영상을 다시 편집하는 일"이
아니라 **코드 한 줄을 고치고 다시 렌더하는 일**이 됩니다.

---

## 2. 바탕에 깔린 원칙 셋

### ① 손으로 적지 않는다

저장소 맨 위 `scripts/sync-counts.mjs` 머리말이 같은 이야기를 합니다. 모아보기 카드에
개수를 손으로 적어 두었더니 1분사회는 열 시간 만에, 낱말은 처음부터 틀린 수였습니다.

**영상은 더 나쁩니다.** 한 번 올리면 고치기 어렵고, 유튜브와 메신저에 그대로 남습니다.
그래서 영상에 나오는 글자 가운데 **사이트에서 가져올 수 있는 것은 전부 가져옵니다** —
사이트 이름, 한 줄 소개, 걸리는 시간, 개수. 영상 코드에 직접 적힌 글귀는 장면을 잇는 말
("수업이 일찍 끝났어요", "어느 교실에서든")뿐입니다.

> **실제로 한 번 걸렸습니다.** 2026-11-23 저장소의 `home/index.html` 에는 문항 1,944 ·
> 차시 영상 192 · 그림 44 로 적혀 있었지만, 데이터의 진짜 수는 2,236 · 427 · 90 이었습니다.
> 사이트는 멀쩡합니다 — `home.yml` 이 발행 직전에 다시 뽑아 올리기 때문입니다.
> 저장소 파일을 그대로 찍었다면 **사이트 어디에도 없는 숫자**가 영상에 박혔을 것입니다.

### ② 그리지 않고, 진짜 화면을 찍는다

사이트 화면을 그림으로 흉내 내지 않습니다. 저장소를 그대로 띄워 **크로미움으로 진짜
사이트를 찍습니다.** 아이콘과 로고도 모아보기 안의 SVG 에서 가져옵니다.

사이트가 바뀌면 `npm run prep` 만 다시 돌리면 영상이 따라옵니다. 흉내 낸 그림이었다면
사이트가 바뀔 때마다 그림이 낡아 갔을 것입니다.

### ③ 조용히 넘어가지 않는다

누를 곳을 못 찾거나, 사이트가 여덟이 아니거나, 아이콘이 없으면 **멈춥니다.**
빈 화면이나 틀린 글자가 영상에 박히는 것보다, 만들다 멈추는 쪽이 낫기 때문입니다.
`sync-counts.mjs` 가 "조용한 0 이 가장 위험하다"고 적어 둔 것과 같은 이유입니다.

## 3. 만드는 순서

```bash
cd intro && npm install
```

```bash
cd intro && npm run prep
```

```bash
cd intro && npm run render
```

`prep` 이 재료를 모으고, `render` 가 영상을 굽습니다. 재료는 전부 `intro/public/` 아래에
떨어지고 **저장소에는 넣지 않습니다**(`.gitignore`). 저장소에 들어가는 것은 **코드와
완성본 mp4 한 벌**뿐입니다.

미리 보며 고치려면 `npm run dev` (Remotion Studio)를 띄웁니다.

## 4. `npm run prep` 이 하는 다섯 가지

`scripts/prep.mjs` 가 아래를 순서대로 부릅니다. 순서가 중요합니다 — ④가 ③의 결과를 씁니다.

### ① 글꼴 — Pretendard 다섯 굵기

`node_modules/pretendard` 에서 Medium·SemiBold·Bold·ExtraBold·Black 을 `public/fonts/` 로
복사합니다.

사이트들이 쓰는 웹폰트는 자주 쓰는 글자만 남긴 **서브셋**인데, 영상 자막에는 거기 없는
글자가 나올 수 있습니다. 그래서 영상만 전체 글꼴을 씁니다.

### ② 로고

`home/favicon.svg` 를 `public/logo.svg` 로 복사합니다. 제목 화면과 마무리 화면에 쓰는
그 로고입니다. 로고를 바꾸면 영상도 자동으로 따라옵니다.

### ③ 효과음 세 개

`remotion.media` 에서 `whoosh` · `mouse-click` · `ding` 을 받아 `public/sfx/` 에 둡니다.
Remotion 이 영상용으로 제공하는 소리입니다. (인터넷이 필요한 유일한 단계입니다.)

### ④ 여덟 사이트의 글귀와 개수 — `scripts/sites.mjs`

→ `public/sites.json`

1. `home/index.html` 을 **사본으로** 뜹니다.
2. 그 사본에 `scripts/sync-counts.mjs --target <사본>` 을 돌립니다. 그러면 저장소 맨 위의
   그 스크립트가 **여덟 사이트의 데이터를 직접 세어** 개수를 채워 줍니다.
3. 사본에서 카드마다 이름(`<h3>`) · 한 줄 소개(`.line`) · 걸리는 시간(`.min`) ·
   개수(`.amt`) · 주소를 읽어 `sites.json` 으로 저장합니다.

**원본 `home/index.html` 은 건드리지 않습니다.** 그 파일은 발행에 닿는 파일이라, 고치면
그 커밋이 곧 모아보기 배포가 됩니다(저장소 맨 위 `CLAUDE.md` 1절).

세는 법을 여기에 다시 쓰지 않고 **`sync-counts.mjs` 를 그대로 돌리는 것**이 핵심입니다.
세는 법이 두 군데 있으면 언젠가 갈라지고, 갈라진 쪽이 조용히 틀립니다.

읽어 온 결과(2026-11-23 기준):

```
짬짬이 게임     전자칠판으로 즐기는 미니게임      3~10분 · 미니게임 105
짬짬이 퀴즈     퀴즈도 풀고, 게임도 하고          3~10분 · 문답 게임 101
짬짬이 낱말     맞히고 외치며, 낱말은 쑥쑥        3~7분  · 문항 2,236
짬짬이 이야기   이야기 한 편에 생각이 와글와글    5~10분 · 이야기 100
짬짬이 영상     준비 없이 바로 트는 교육 영상     1~10분 · 영상 504
짬짬이 수업영상 차시마다, 수업에 바로 쓰는 영상   1~10분 · 차시 영상 427
짬짬이 그리기   화면 따라 쓱쓱, 종이 위에 짠      5~10분 · 그림 90
짬짬이 그림책   넘기며 읽어 주는 옛이야기         3~5분  · 그림책 6
```

여덟이 아니면 멈춥니다.

### ⑤ 사이트 화면 찍기 — `scripts/capture.mjs`

→ `public/shots/*.png` 와 크기를 적어 둔 `public/shots/shots.json` (모두 **22장**)

`scripts/serve.mjs` 가 저장소 맨 위를 뿌리로 하는 작은 정적 서버를 띄웁니다. 여덟 사이트가
전부 빌드 단계 없는 정적 사이트라, 이러면 `/game/` · `/quiz/` … 가 **발행된 모습 그대로**
열립니다. 그 위를 크로미움(Playwright)이 1920×1080 · **2배 선명도**로 찍습니다.

**(가) 첫 화면 아홉 장** — 모아보기와 여덟 사이트

창 높이를 그대로 쓰면 내용이 짧은 사이트(이야기·낱말)는 아래가 허옇게 빕니다.
그렇다고 `scrollHeight` 를 재면 안 됩니다 — 여덟 사이트 모두 바탕이 창 높이만큼 늘어나
**늘 1080 이 나옵니다.** 그래서 **자식 없는 요소들의 가장 아래**, 곧 글자와 그림이 실제로
끝나는 자리를 재고 여백 56px 을 더해 창을 줄인 뒤 다시 찍습니다.

| 화면 | 크기 |
| --- | --- |
| `home.png` | 1920×909 |
| `game.png` · `quiz.png` · `video.png` · `1min.png` · `draw.png` · `picturebook.png` | 1920×1080 |
| `word.png` | 1920×980 |
| `story.png` | 1920×755 |

모아보기를 찍기 직전에 **카드의 개수만 ④에서 뽑아 둔 값으로 덮어씁니다.** 저장소 파일이
낡아 있어도 영상에는 사이트와 같은 수가 나오게 하려는 것입니다.

**(나) 활동 화면 네 장** — 실제로 눌러서 들어간 화면

| 화면 | 가는 길 | 기다림 |
| --- | --- | --- |
| `game-play.png` | `/game/games/dice-sum/` → `.btn-play` | 6.5초 (3·2·1 세는 동안을 지나 실제로 노는 장면까지) |
| `word-play.png` | `/word/` → `#type-grid-quiz` 첫 카드 → `#btn-start` → `#quiz-prompt` | 1.5초 |
| `draw-step.png` | `/draw/` → `#cardGrid` 첫 카드 → `[data-act="start"]` | 14초 (획이 여러 개 그려질 만큼) |
| `book-page.png` | `/picturebook/` → `[data-act="today"]` → `#startBtn` | 3.5초 |

누를 곳을 못 찾으면 **어느 선택자를 못 찾았는지 말하고 멈춥니다.** 사이트의 단추 이름이
바뀌면 이 표와 `capture.mjs` 를 함께 고쳐야 합니다.

**(다) 바로가기 띠 한 장** — `switcher.png` (571×62)

**이야기 화면에서 찍습니다.** 사이트는 바로가기에 **자기 자신을 빼고** 걸기 때문에, 게임
화면에서 찍으면 정작 맨 앞의 게임 아이콘이 빠집니다. 좌우로 여백을 주면 옆에 있는 소리·
전체화면 단추가 딸려 들어오므로 띠에 딱 맞게 오립니다.

**(라) 아이콘 여덟 장** — `icon-<사이트>.png` (각 960×960, 배경 투명)

머리띠의 44px 바로가기를 오리면 영상에서 뿌옇습니다. 그래서 모아보기 안에 들어 있는
**SVG 원본**(`<symbol id="i-game">` 같은)을 480px 로 한 번 더 그려서 찍습니다.
찍는 동안만 바탕을 투명으로 바꿉니다(`omitBackground` 는 이미 그려진 색을 지우지 못합니다).

### ⑥ 배경음악 — `scripts/make-bgm.mjs`

→ `public/bgm.wav` (44.1kHz 스테레오 16비트, 55.4초)

**남의 곡을 쓰지 않습니다.** 코드가 파형을 직접 계산해 WAV 를 씁니다. 그래서 유튜브
저작권(Content ID)에 걸릴 일이 없습니다.

- 밝은 **D장조, 100 BPM, 4/4 박자 23마디**. 화성은 D–A–Bm–G (I–V–vi–IV)
- 악기도 전부 코드입니다 — 패드(살짝 어긋난 사인 둘), 마림바, 종소리, 베이스,
  킥·박수·하이햇
- 잔향은 Schroeder 방식(빗살 넷 + 전역 통과 둘)을 직접 구현했습니다
- 구성: 1~2마디 패드·마림바만 → 3~20마디 리듬이 들어옴 → 7마디부터 종소리 멜로디 →
  21~23마디 리듬이 빠지고 마지막 화음이 울리며 끝
- 난수 씨앗이 고정(`20261123`)이라 **같은 코드면 늘 같은 소리**가 납니다
- 마지막에 최고점을 0.85 로 맞추고 `tanh` 로 부드럽게 눌러 클리핑을 막습니다

## 5. 영상의 뼈대

`src/IntroVideo.tsx` 가 장면을 늘어놓습니다. 장면 사이는 **12프레임씩 겹쳐** 넘어갑니다.

```
INTRO_LEN = 모든 장면 길이의 합 − 12 × (장면 수 − 1)
          = 1725 − 72 = 1653프레임 = 55.1초
```

| # | 장면 | 프레임 | 초 | 내용 | 쓰는 화면 |
| --- | --- | --- | --- | --- | --- |
| 1 | `Hook` | 105 | 3.5 | 먹색 바탕 — "수업이 일찍 끝났어요 / 남은 10분, 뭘 하지?" | — |
| 2 | `Title` | 140 | 4.7 | 짬짬이 교실 · 짬짬이.com | `logo.svg` |
| 3 | `Eight` | 185 | 6.2 | 모아보기 한 화면 + 아이콘 여덟이 차례로 통통 | `home.png`, `icon-*.png` |
| 4 | `Sites` | 800 | 26.7 | 사이트 여덟 칸(100프레임 = 3.3초씩) | 첫 화면 여덟 + 활동 화면 넷 |
| 5 | `Switcher` | 165 | 5.5 | 머리 위 바로가기 줄 · 전체 보기 | `switcher.png` |
| 6 | `Free` | 160 | 5.3 | 모두 무료 · 설치 없음 · 로그인 없음 · 큰 화면 | — (선 아이콘) |
| 7 | `Outro` | 170 | 5.7 | 짬짬이 교실 · 짬짬이.com | `logo.svg`, `icon-*.png` |

전환은 먹색 화면이 드나드는 곳(처음과 끝)만 **겹쳐 사라지기**(fade)이고, 나머지는
**옆으로 밀기**(오른쪽에서 들어옴)입니다.

### 사이트 한 칸의 안쪽 (`src/scenes/Sites.tsx`)

- 위쪽에 사이트 화면, 아래 띠에 **아이콘 · 이름(사이트 색 알약) · 한 줄 소개 ·
  걸리는 시간 · 개수**
- 화면은 100프레임 동안 1 → 1.03 으로 아주 천천히 다가갑니다
- 활동 화면이 있는 넷(게임·낱말·그리기·그림책)은 **50프레임째부터 16프레임에 걸쳐
  아래에서 밀고 올라옵니다**

> 처음에는 두 화면을 겹쳐 사라지게 했는데, 빽빽한 사이트 화면 둘이 포개지니 **고장난
> 것처럼 보였습니다.** 밀어 올리면 "눌러 들어갔구나"가 눈에 보입니다.

사이트마다 세로 길이가 다르므로, 화면은 띠 위 공간의 한가운데에 놓입니다.

## 6. 소리

| 소리 | 어디에 | 크기 |
| --- | --- | --- |
| 배경음악 `bgm.wav` | 처음부터 끝까지 | 1.0 — 0.5초 들어오고 마지막 1.5초 사라짐 |
| `whoosh` | `Eight` 아이콘이 뜰 때, `Sites` 칸이 바뀔 때마다 | 0.3 |
| `mouse-click` | `Switcher` 에서 띠가 떠오를 때 | 0.5 |
| `ding` | `Outro` 에서 제목이 튀어오를 때 | 0.45 |

내레이션은 넣지 않았습니다. 자막과 화면만으로 끌고 갑니다 — 딸깍 보결 영상과 같은 방식이고,
목소리를 새로 녹음하지 않아도 사이트가 바뀔 때마다 다시 만들 수 있기 때문입니다.

음량은 확인해 두었습니다.

```bash
ffmpeg -i intro/jjam-classroom-intro.mp4 -af ebur128=peak=true -f null -
```

통합 **−16.4 LUFS**(유튜브는 −14 LUFS 안팎으로 맞추므로 올리면 조금 커집니다),
트루피크 **−2.0 dBFS** 로 여유가 있습니다.

## 7. 고치고 싶을 때 어디를 건드리나

| 고치고 싶은 것 | 건드릴 곳 |
| --- | --- |
| 장면 순서·길이·전환 | `src/IntroVideo.tsx` 의 `SCENES` |
| 어느 한 장면의 글이나 배치 | `src/scenes/<장면>.tsx` |
| 사이트 띠의 색, 어떤 화면을 쓸지 | `src/sites.ts` 의 `LOOK` |
| 사이트 이름·한 줄 소개·개수 | **여기서 고치지 않습니다** — `home/index.html` 과 각 사이트 데이터 |
| 색·글꼴·화면 틀 | `src/theme.tsx` (색은 모아보기 `:root` 와 같은 값) |
| 어떤 화면을 찍을지, 어디를 누를지 | `scripts/capture.mjs` |
| 배경음악 | `scripts/make-bgm.mjs` |
| 영상 화질 | `package.json` 의 `render` 스크립트(`--crf=20`) |

사이트 화면만 바뀌었다면 `npm run prep && npm run render`, 영상 코드만 고쳤다면
`npm run render` 만 돌리면 됩니다.

### 사이트가 아홉 번째로 늘면

1. 모아보기(`home/`)와 바로가기(`game/shared/jjam-switcher.js`)에 먼저 넣습니다
   — 저장소 맨 위 `CLAUDE.md` 를 따릅니다
2. `scripts/sync-counts.mjs` 의 `SITES` 에 세는 법을 더합니다
3. `intro/src/sites.ts` 의 `LOOK` 에 색과 쓸 화면을 더합니다
4. `intro/scripts/capture.mjs` 의 `FRONTS` 에 주소를 더합니다
5. `intro/scripts/sites.mjs` · `src/sites.ts` 의 "여덟" 확인을 아홉으로 고칩니다
6. `npm run prep && npm run render`

5번을 일부러 고치게 해 두었습니다. 숫자를 박아 두면 **사이트가 늘었는데 영상에는 안 나오는
일**이 조용히 일어나기 때문입니다.

## 8. 이 폴더는 배포에 닿지 않습니다

`intro/` 는 저장소에서 **유일하게 사이트가 아닌 내용 폴더**입니다.

- `publish-dispatch.yml` 의 `paths` — `game/` · `quiz/` · `video/` · `story/` · `word/` ·
  `1min/` · `draw/` · `picturebook/` 만 봅니다
- `home.yml` 의 `paths` — `home/**` 와 자기 자신, 그리고 개수가 나오는 데이터 파일만 봅니다

**어느 쪽에도 `intro/` 가 없습니다.** 그래서 여기를 고치고 머지해도 아홉 사이트 중 어느
것도 다시 발행되지 않습니다. 그러라고 따로 둔 자리입니다.

반대로 이 폴더를 `home/` 안으로 옮기면 **커밋 하나하나가 곧 모아보기 배포**가 됩니다.
옮기지 마세요.

만드는 동안에도 `home/index.html` 은 사본으로만 다루고 원본은 건드리지 않습니다(4-④).

## 9. CI 를 걸지 않은 이유

`npm run lint`(eslint + tsc)가 `prep` 의 결과물인 `public/sites.json` 과
`public/shots/shots.json` 을 읽어 타입을 맞춥니다. 그래서 검사하려면 러너에 크로미움을 깔고
캡처까지 돌려야 합니다 — 몇 분이 걸리고, 사이트 아홉 곳을 다 띄워야 합니다.

본보기로 삼은 딸깍 보결 저장소도 `video/` 에 CI 를 걸지 않았습니다. 같은 방식을 따랐습니다.
대신 손으로 아래를 돌립니다.

```bash
cd intro && npm run prep && npm run lint && npm run render
```
